# Fase 0 — Setup Implementation Plan

> **Nota de alcance:** esta fase es scaffolding de herramientas (carpetas, package.json,
> Vite, Supabase CLI local), no lógica de negocio. Los pasos no siguen el ciclo
> red/green de TDD porque no hay comportamiento que testear todavía — el
> `index.html` actual se mueve tal cual, sin cambiar una sola línea de su
> `<script>`/`<style>`. La disciplina TDD aplica a partir de la Fase 2 (capa de
> datos / sync), donde sí hay lógica pura que testear.

**Goal:** Dejar el proyecto actual (`~/Documents/Horario/index.html` monolítico)
corriendo bajo Vite + git, con la estructura de carpetas que las fases 1-6
van a necesitar, sin cambiar ningún comportamiento visible de la app.

**Architecture:** Vite sirve `index.html` en la raíz tal cual existe hoy (Vite
no transforma `<script>` sin `type="module"`, así que el bloque de 400 líneas
de JS inline pasa intacto). Los assets estáticos (`manifest.json`,
`service-worker.js`, íconos) se mueven a `public/` para que Vite los copie
sin procesar. Se crean carpetas vacías `src/data/`, `src/themes/`,
`src/repositories/`, `supabase/` como andamiaje para fases futuras.

**Tech Stack:** Vite (dev server + build), Supabase CLI (local), git.

---

## Archivos a tocar

- Crear: `package.json`, `vite.config.js`, `.env.example`, `.gitignore`
- Crear: `CHANGELOG.md` (arranca aquí, se completa fase por fase)
- Modificar: `README.md` (agrega sección de desarrollo, preserva la existente)
- Mover: `Icons/*.png` → `public/icons/*.png` (corrige mismatch de mayúsculas
  que rompería en GitHub Pages, que es case-sensitive a diferencia de macOS)
- Mover: `manifest.json` → `public/manifest.json`
- Mover: `service-worker.js` → `public/service-worker.js`
- Sin cambios: `index.html` (se queda en la raíz, contenido intacto)
- Crear (vacías, con `.gitkeep`): `src/data/`, `src/data/repositories/`,
  `src/themes/`, `scripts/`
- Generado por `supabase init`: `supabase/config.toml`, `supabase/.gitignore`

## Tareas

### Tarea 1: Baseline en git

- [ ] `git init` en `~/Documents/Horario`
- [ ] `git add -A && git commit -m "chore: snapshot del PWA original antes de migrar"`
  — así queda un punto de referencia exacto del código de la amiga antes de
  tocar nada, recuperable con `git show <hash>:index.html` si algo se rompe.

### Tarea 2: Reestructurar assets estáticos

- [ ] Crear `public/icons/`, mover los 3 PNGs de `Icons/` ahí, borrar `Icons/`
- [ ] Mover `manifest.json` → `public/manifest.json` (contenido sin cambios,
  las rutas relativas `icons/icon-192.png` siguen resolviendo igual porque
  Vite sirve `public/` en la raíz del sitio)
- [ ] Mover `service-worker.js` → `public/service-worker.js`
- [ ] Verificar: `index.html` no requiere ningún cambio porque sus referencias
  (`href="icons/apple-touch-icon.png"`, `href="manifest.json"`,
  `register("service-worker.js")`) ya son rutas relativas a la raíz del sitio.

### Tarea 3: `package.json` + Vite

- [ ] Crear `package.json` con `"type":"module"`, scripts `dev`/`build`/`preview`,
  devDependency `vite`, y dependencies del stack objetivo
  (`@supabase/supabase-js`, `idb`, `date-fns`, `html2canvas`) para que
  `npm install` deje todo listo de una vez para las fases siguientes.
- [ ] Crear `vite.config.js` con `base:'./'` (portátil a cualquier nombre de
  repo de GitHub Pages, sin hardcodear el subpath).
- [ ] `npm install`
- [ ] `npm run dev` y verificar en el navegador que la app carga igual que
  antes (grid, today card, todos, dark mode, notas) — cero regresión visual
  o funcional.
- [ ] Ctrl+C, `npm run build` para confirmar que el build de producción
  también genera `dist/index.html` sirviendo los mismos assets.

### Tarea 4: Supabase CLI local

- [ ] Instalar CLI: `brew install supabase/tap/supabase`
- [ ] `supabase init` en la raíz del proyecto (genera `supabase/config.toml`)
- [ ] `supabase start` — **bloqueado hasta que Docker Desktop esté instalado
  y corriendo** (el usuario lo está instalando por su cuenta). Se documenta
  el comando pendiente en el reporte final de la fase; no se asume que ya
  corrió.

### Tarea 5: `.env.example`, `.gitignore`, README, CHANGELOG

- [ ] `.env.example` con `VITE_SUPABASE_URL` y `VITE_SUPABASE_ANON_KEY`
  (valores de ejemplo, no reales — se llenan cuando `supabase start` imprima
  las credenciales locales en Fase 1).
- [ ] `.gitignore`: `node_modules/`, `dist/`, `.env`, `.env.local`,
  `.DS_Store`, `supabase/.branches/`, `supabase/.temp/`.
- [ ] `README.md`: agrega sección "Desarrollo local" arriba de las secciones
  existentes (que siguen siendo válidas — la app sigue siendo 100% local
  hasta que cierre Fase 2). No se borra nada del contenido actual.
- [ ] `CHANGELOG.md`: primera entrada, describiendo el arranque de la
  migración (herramientas agregadas, cero cambio de comportamiento).

### Tarea 6: Commit de cierre de fase

- [ ] `git add -A && git commit -m "chore: setup Vite + Supabase CLI local (Fase 0)"`
- [ ] Reportar al usuario: qué se hizo, cómo verificarlo, qué quedó
  pendiente (Docker/`supabase start`), y esperar confirmación antes de
  Fase 0.5.
